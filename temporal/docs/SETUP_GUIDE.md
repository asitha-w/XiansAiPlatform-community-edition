# Temporal Setup Guide

## Overview

This Temporal setup uses the generic `temporalio/server` image with full TLS/mTLS support and proper configuration.

## Components

### 1. Temporal Server (`temporalio/server`)
- **Frontend**: Port 7233 (gRPC) - Client connections with mTLS
- **Matching**: Port 7235 - Task queue management
- **History**: Port 7234 - Workflow execution history
- **Worker**: Port 7239 - Internal background workers
- **Metrics**: Port 9090 - Prometheus metrics

### 2. Databases
- **PostgreSQL**: Workflow execution metadata
- **Elasticsearch**: Workflow visibility and search

### 3. Temporal UI
- Web interface on port 8080
- Connects to frontend via mTLS

## Configuration Files

### `config/config.yaml`
Main Temporal server configuration:
- **Global settings**: TLS/mTLS for all services
- **Persistence**: PostgreSQL and Elasticsearch
- **Services**: All four Temporal services
- **Dynamic config**: Points to dynamicconfig files

### `dynamicconfig/development-es.yaml`
Runtime configuration overrides:
- Elasticsearch settings
- ID length limits
- Feature flags

### `certs/`
mTLS certificates (auto-generated):
- `ca.crt` - Certificate Authority
- `temporal.crt/key` - Server certificate (SAN: temporal, localhost)
- `temporal-ui.crt/key` - UI client certificate

## Setup Process

### 1. Prerequisites
```bash
# Ensure PostgreSQL is running
docker-compose -f ../postgresql/docker-compose.yml up -d

# Ensure network exists
docker network create xians-community-edition-network 2>/dev/null || true
```

### 2. Generate Certificates
```bash
# From project root
./scripts/create-secrets.sh temporal
```

This creates:
- Global CA in `tmp/certs/`
- Temporal-specific certs in `temporal/certs/`
- Updates `temporal/.env.local` with certificate paths

### 3. Initialize Database Schema
```bash
cd temporal
./init-temporal-schema.sh
```

This:
- Waits for PostgreSQL
- Creates `temporal` and `temporal_visibility` databases
- Runs schema migrations
- **Only needs to run once** (or after reset)

### 4. Start Temporal Server
```bash
docker-compose up -d
```

### 5. Register Namespace
```bash
./register-namespace.sh
```

This creates the `xiansai` namespace for workflow execution.

### 6. Verify Setup
```bash
# Check server health
docker exec temporal tctl cluster health

# Verify namespace
docker exec temporal tctl --namespace xiansai namespace describe

# Check mTLS is working
docker logs temporal 2>&1 | grep -i tls
```


## Security

### mTLS Configuration
- **Server Certificate**: `temporal.crt` with SANs: `temporal`, `localhost`
- **Client Certificates**: 
  - Temporal UI: `temporal-ui.crt` (CN: temporal-ui)
  - .NET Server: Uses CA to generate client cert
- **Certificate Authority**: Shared `ca.crt` for all services
- **Permissions**: All certs are 644 (readable by Docker containers)

### TLS Verification
- **Server**: Validates client certificates against CA
- **Clients**: Validate server certificate hostname
- **Mutual Authentication**: Both server and client prove identity

## Troubleshooting

### "Connection refused" on port 7233
```bash
# Check if Temporal is running
docker ps | grep temporal

# Check logs for errors
docker logs temporal

# Verify config is valid
docker exec temporal cat /etc/temporal/config/config.yaml
```

### "TLS handshake failed"
```bash
# Verify certificates are mounted
docker exec temporal ls -la /etc/temporal/certs/

# Check certificate validity
docker exec temporal openssl x509 -in /etc/temporal/certs/temporal.crt -text -noout

# Verify CA matches
docker exec temporal openssl verify -CAfile /etc/temporal/certs/ca.crt /etc/temporal/certs/temporal.crt
```

### Schema initialization fails
```bash
# Check PostgreSQL is accessible
docker exec temporal pg_isready -h postgresql -U dbuser

# Manually verify database
docker exec postgresql psql -U dbuser -d temporal -c "\dt"

# Re-run schema setup
./init-temporal-schema.sh
```

### Namespace not found
```bash
# Check if namespace exists
docker exec temporal tctl namespace list

# Re-register namespace
./register-namespace.sh
```
