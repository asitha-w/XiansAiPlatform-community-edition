# mTLS Configuration Structure

## Overview
This document describes the mTLS (Mutual TLS) setup for secure communication between Server and Temporal services using a single global CA.

## Certificate Generation Flow

```bash
create-secrets.sh
  ├─> Checks CERTS_DIR environment variable
  ├─> Falls back to project temp: ./tmp/certs (self-contained)
  └─> generate_ssl_certificate("password", "$CERT_STORAGE_DIR")
       └─> Generates CA files in determined location
```

## Certificate Storage Location (Cross-Platform)

**Default behavior** (no `CERTS_DIR` set):
```
Project-relative: ./tmp/certs/
```
- ✅ Self-contained within project
- ✅ Cleaned by reset-all.sh
- ✅ Works on Linux, Mac, Windows (Docker Desktop)
- ✅ No host system pollution

**Custom location** (set `CERTS_DIR` in `.env`):
```bash
# Linux/Mac example
CERTS_DIR=/home/user/.xiansai/certs

# Windows example (Docker Desktop compatible paths)
CERTS_DIR=C:/Users/MyUser/.xiansai/certs
# or
CERTS_DIR=/c/Users/MyUser/.xiansai/certs
```

## File Structure

```
$CERT_STORAGE_DIR/
  ├─ ca.crt     # CA certificate (PEM format)
  ├─ ca.key     # CA private key (PEM format)
  └─ ca.pfx     # CA as PFX/PKCS12 (for .NET)
```

## Configuration Injection

### Server (`server/.env.local`)
Uses **base64-encoded** certificates (for .NET application):

```bash
Certificates__AppServerPfxBase64=<base64 encoded ca.pfx>
Certificates__AppServerCertPassword=<auto-generated password>
Certificates__ServerRootCACertBase64=<base64 encoded ca.crt>
```

**Purpose:**
- `AppServerPfxBase64`: CA with private key for signing certificates
- `ServerRootCACertBase64`: CA certificate for trusting Temporal server

### Temporal (`temporal/.env.local`)
Uses **file paths** (mounted volumes):

```bash
TEMPORAL_CERTS_HOST_DIR=<auto-generated path from $CERT_STORAGE_DIR>
TEMPORAL_TLS_CA_CERT=/etc/temporal/certs/ca.crt
TEMPORAL_TLS_CA_KEY=/etc/temporal/certs/ca.key
TEMPORAL_TLS_CA_PASSWORD=<auto-generated password>
```

**Purpose:**
- `TEMPORAL_CERTS_HOST_DIR`: Host path to mount (cross-platform compatible)
- CA files mounted from host `$TEMPORAL_CERTS_HOST_DIR` to container `/etc/temporal/certs/`
- Used for generating and signing Temporal server certificates

## Key Design Decisions

1. **Single Global CA**: One CA for all services in Docker deployment
2. **mTLS by Default**: No toggle flags - mTLS is the standard configuration
3. **Self-Contained Storage**: 
   - Uses project-relative temp directory by default (`./tmp/certs`)
   - Fully isolated - no host system dependencies
   - Cleaned automatically by `reset-all.sh`
   - Configurable via `CERTS_DIR` for custom locations
   - Works on Linux, Mac, and Windows (Docker Desktop)
4. **Format Separation**: 
   - Server uses base64 strings (follows .NET pattern)
   - Temporal uses file paths (follows standard Docker pattern)
5. **Logical Grouping**: CA certificate is under `Certificates__` section (not `Temporal__`)

## Scripts

- `scripts/certificate-generator.sh`: Generates CA and saves to `./certs/`
- `scripts/create-secrets.sh`: Injects CA into service `.env.local` files

## Usage Examples

### Default (Project Temp Directory)
```bash
# Just run start-all.sh - certificates stored in ./tmp/certs
./start-all.sh

# Certificates are at: ./tmp/certs/
# Clean up with: ./reset-all.sh
```

### Custom Location
```bash
# Set in .env file (Linux/Mac)
echo "CERTS_DIR=/home/user/.xiansai/certs" >> .env
./start-all.sh

# Or export for single run
export CERTS_DIR=/home/user/.xiansai/certs
./start-all.sh
```

### Windows Users (Docker Desktop)
```bash
# In .env file - use forward slashes or Docker Desktop style paths
CERTS_DIR=C:/Users/MyUser/.xiansai/certs
# or
CERTS_DIR=/c/Users/MyUser/.xiansai/certs

# Then run
./start-all.sh
```
